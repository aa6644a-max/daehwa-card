# 대화카드

투명필름 대화카드를 휴대폰 화면 위에 올려놓고 감상하는 관상용 웹 화면.
아이폰·안드로이드 모두 브라우저로 접속해 사용한다. 설치할 앱은 없다.

## 화면 구성

```
┌──────────────────┐
│  今、対話をしよう。  │  ← 상단 아트워크 (길게 누르면 설정)
│  あなたをもっと…    │     assets/top-<lang>.png
├──────────────────┤
│  ╭────────────╮  │
│  │            │  │  ← 흰 무대. 여기에 카드를 올린다.
│  │    카드     │  │     가운데 둥근 사각형은 CSS 가이드
│  │            │  │     터치 반응 요소가 하나도 없다.
│  ╰────────────╯  │
├──────────────────┤
│  スマホの上に…     │  ← 하단 아트워크 (두 번 탭하면 전체화면)
│  @daehwa.scene   │     assets/bottom-<lang>.png
└──────────────────┘
```

화면 전체가 **밝기 100% ↔ 85% 사이를 1초 주기로 무한 반복**한다.
QR 로 들어온 사람이 전부 같은 리듬을 보도록 1초로 고정해 두었다.
파형은 호흡(균일)과 심장박동(쿵쿵-쉼) 중에 고를 수 있다.

## 아트워크 교체

원본 디자인은 **화면 전체 한 장**(2250 × 5000, 9:20)으로 온다.
상단 문구 / 카드 가이드 / 하단 문구가 한 파일에 들어 있으므로 **위아래를 잘라서 쓴다.**

| 조각 | 원본에서 자르는 범위 | 규격 | 파일 |
|---|---|---|---|
| 상단 | y 0 ~ 1000 | 2250 × 1000 (2.25:1) | `assets/top-<lang>.png` |
| 하단 | y 4090 ~ 5000 | 2250 × 910 (2.47:1) | `assets/bottom-<lang>.png` |

가운데 카드 가이드는 잘라내지 않고 **CSS 로 다시 그린다**(`#card-guide`).
화면 높이에 맞춰 늘어나므로 긴 폰에서 카드 자리가 더 넓어진다.

새 디자인이 오면 위 y 범위로 자르면 된다. 다른 언어도 같은 규격을 지킬 것.

### 아트워크 높이와 카드 자리는 맞바꾸는 관계다

문구를 크게 넣을수록 카드 놓을 흰 영역이 줄어든다.
`styles.css` 의 **`--art-max-h`**(기본 `17vh`)가 이 균형을 정한다.

실측(세이프에어리어·주소창 제외 전):

| 기기 | 상단 | 흰 무대 | 하단 | 카드 88mm |
|---|---|---|---|---|
| iPhone 15 (393×852) | 145px | **92.8mm** | 145px | 들어감 |
| Galaxy S24 (360×780) | 133px | **94.5mm** | 133px | 들어감 |
| iPhone 15 Pro Max | 158px | **102mm** | 158px | 여유 |
| iPhone SE (375×667) | 113px | 68.7mm | 113px | **안 들어감** |

문구를 더 크게 보이고 싶으면 `--art-max-h` 를 올리고, 카드 자리를 더 주려면 내린다.
세로 700px 이하 기기에서는 자동으로 `14vh` 로 줄어든다.

### 카드 가이드 크기

가이드는 원본 디자인대로 **가로 89%**, 세로는 남는 흰 영역 전체다.
iPhone 15 기준 약 53.6 × 90.8mm 로, 실제 카드(63 × 88mm)보다 **가로가 9mm 좁다.**
화면 폭 자체가 64.9mm 뿐이라 63mm 가이드를 그리려면 화면의 97% 를 써야 해서
디자인 비율을 버려야 한다. 지금은 카드가 가이드를 살짝 덮는 상태다.
바꾸려면 `styles.css` 의 `--guide-w` 를 조절한다.

## 다국어

QR 로 들어온 사람은 **항상 언어 선택 화면부터** 본다(선택을 기억하지 않는다).
여러 나라 사람이 한 대를 돌려볼 수 있는 상황이라 매번 고르게 했다.

| 코드 | 언어 | `html[lang]` | 아트워크 |
|---|---|---|---|
| `ko` | 한국어 | `ko` | `top-ko.png` · `bottom-ko.png` (자리표시) |
| `en` | English | `en` | `top-en.png` · `bottom-en.png` (자리표시) |
| `ja` | 日本語 | `ja` | `top-ja.png` · `bottom-ja.png` **(실제 디자인)** |
| `zh` | 繁體中文 (대만·홍콩) | `zh-Hant` | `top-zh.png` · `bottom-zh.png` (자리표시) |

`?lang=ja` 처럼 붙이면 선택 화면을 건너뛰고 바로 그 언어로 들어간다.
**나라별 QR 을 따로 뿌리고 싶을 때 이 주소를 쓰면 된다.**

언어를 바꾸려면 상단 문구를 길게 눌러 설정 패널 > **언어 다시 선택**.

### 언어에 따라 바뀌는 것

- 상단·하단 아트워크 이미지
- 안내 문구 전부(홈 화면 추가 · 전체화면 불가 · 화면 꺼짐 방지)
- `html[lang]` 과 글꼴 — 같은 한자도 일본어와 중국어는 자형이 다르므로 반드시 필요하다

**설정 패널은 운영자용이라 한국어로 둔다.**

상단 '대화카드' 텍스트는 제거했다. 이제 상단 아트워크 이미지가 그 자리를 대신한다.

### 언어를 추가하려면

1. `app.js` 의 `LANGS`, `HTML_LANG`, `I18N` 에 코드를 추가
2. `index.html` 의 `#langpick` 에 버튼 추가 (`data-lang`, `lang` 속성 둘 다)
3. `assets/top-<코드>.png`, `assets/bottom-<코드>.png` 추가
4. `sw.js` 의 `SHELL` 목록에 두 파일 추가하고 `CACHE` 버전 올리기
5. 필요하면 `styles.css` 에 그 언어 글꼴 스택 추가

## 호흡 설정 (숨김 기능)

상단 **'대화카드' 문구를 1초간 길게 누르면** 설정 패널이 열린다.
일반 사용자는 알 수 없고, 값은 그 기기에만 저장된다.

| 항목 | 범위 | 기본값 |
|---|---|---|
| 파형 | 호흡 / 심장박동 | 호흡 |
| 주기 | 0.5 ~ 12초 (심장박동은 0.7초부터) | **1초** |
| 어두워지는 정도 | 0 ~ 40% | 15% |
| 곡선 | 부드럽게 / 일정하게 / 깊게 (호흡 전용) | 부드럽게 |
| 상단바 색 | 고정 / 동기화(보정) / 동기화(보정 없음) | 동기화(보정) |
| 카드 가이드 크기 | 80 ~ 130% | 100% |

URL 파라미터로도 지정할 수 있다: `?wave=heart&period=0.7&depth=22&guideScale=110`

### 카드 가이드 크기 — 실물 카드에 맞춰 즉석에서 키우기/줄이기

가운데 흰 무대의 카드 자리(`#card-guide`)는 이미지가 아니라 CSS 사각형이라 크기를
런타임에 바로 조절할 수 있다. 설정 패널의 **'카드 가이드 크기'** 슬라이더가
`--guide-scale` 을 바꿔 `#card-guide` 를 가운데 기준으로 확대/축소한다(`transform: scale()`).

100%보다 키우면 위아래 아트워크 자리를 살짝 덮을 수 있다 — 의도한 동작이다.
실물 카드를 화면에 대보면서 딱 맞는 값을 찾은 뒤, 그 값을 아래 '기본값을 바꿀 때'
절차대로 `DEFAULTS.guideScale` 에 반영하면 QR 로 들어오는 모든 사람에게 적용된다.

`guideScale` 은 기존 저장 데이터에 없던 새 필드라 `STORE_KEY` 버전을 올리지 않아도
안전하다(`load()` 가 필드별로 기본값을 채워 넣는다) — 다만 `DEFAULTS.guideScale` 자체를
바꾸면 이미 슬라이더를 만져 저장된 기기는 그 옛 값을 계속 쓰니, 그런 기기까지 새
기본값으로 되돌리고 싶다면 다른 값들처럼 버전을 올려야 한다.

### 기본값을 바꿀 때

`app.js` 의 `DEFAULTS` 와 `styles.css` 의 `:root --period` 를 **둘 다** 고치고,
`app.js` 의 `STORE_KEY` 버전(`...v2`)도 반드시 올린다.
버전을 안 올리면 예전에 접속해 슬라이더를 만졌던 기기는 저장된 옛 값을 계속 쓰기 때문에
QR 로 들어온 사람마다 다른 주기를 보게 된다.

### 파형

- **호흡** — 사인파처럼 균일하게 어두워졌다 밝아진다. 한 주기에 1회 변화.
- **심장박동** — 쿵(6%) · 쿵(20%) 두 번 빠르게 어두워진 뒤 주기의 나머지 65%를 쉰다.
  한 주기에 2회 변화. 슬라이더에 BPM 이 함께 표시된다.

### 주기 하한이 파형마다 다른 이유

광과민성 발작 기준(WCAG 2.3.1)은 **초당 3회**를 넘는 번쩍임을 금지한다.
흰 화면에 검은 레이어를 15%만 덮어도 상대휘도가 1.0 → 0.69 로 떨어져
"번쩍임" 임계(변화 10% 이상 + 어두운 쪽 휘도 0.8 미만)에 해당하므로 이 제한을 받는다.

- 호흡은 한 주기에 1회 → 하한 **0.5초** (초당 2회)
- 심장박동은 한 주기에 2회 → 하한 **0.7초** (초당 2.9회, 약 86 BPM)

파형을 바꾸면 주기가 자동으로 그 하한까지 올라간다. 하한을 낮추지 말 것.

실물 카드로 맞춰본 뒤 마음에 드는 값이 나오면 `styles.css` 의 `:root` 기본값과
`app.js` 의 `DEFAULTS` 를 그 값으로 바꿔 모든 사용자에게 적용한다.

## 기본 시청 방식은 "주소창 있는 브라우저 탭"이다

전시회 방문객은 대부분 QR 을 찍고 바로 본다 — 홈 화면 추가도, 전체화면도 강요하지 않는다.
특히 해외(주로 일본) 방문객은 아이폰 비중이 높은데, **iPhone Safari 는 웹 전체화면 API 가
아예 없다.** 그래서 화면 규격은 애초부터 "아이폰 Safari/Chrome, 주소창 켜진 채"를
기준으로 잡는다. 전체화면·홈 화면 추가는 강제하지 않고 아래에 남긴 보조 수단일 뿐이다.

## OS 상단바(시계 · 배터리) 숨기기 — 보조 수단, 강제하지 않음

플랫폼마다 가능 여부가 다르다.

| 플랫폼 | 상단바 숨김 | 방법 |
|---|---|---|
| 안드로이드 | **가능(선택)** | 하단 배너를 두 번 탭 — **안드로이드 전용 이스터에그**, 안내 없이 숨겨둔 기능 |
| 아이폰 | **불가능** | `Element.requestFullscreen` 자체가 없음 — 아래 차선책 적용 |

예전에는 화면 아무 데나 탭해도 자동으로 전체화면을 시도했으나 제거했다. 방문객 대부분이
쓰는 아이폰에서는 어차피 안 되고(API 없음), 되는 안드로이드에서도 QR 찍자마자 화면이
바뀌어버리는 게 오히려 낯설다. 지금은 하단 배너 두 번 탭으로만 켜지는 숨은 기능이다.

iPhone Safari 는 Fullscreen API 를 지원하지 않고, 홈 화면에 추가해도 상태바가 남는다.
대신 `apple-mobile-web-app-status-bar-style` 을 `black-translucent` 로 두었다.
이러면 상태바 글자가 흰색이 되어 순백 배경 위에서 거의 보이지 않고,
웹 내용이 상태바 아래까지 깔린다.

주의: 화면이 어두워지는 순간(밝기 85%)에는 흰 시계 글자가 옅은 회색 배경 위에 놓여
살짝 드러날 수 있다. 어둡기를 키울수록 더 드러난다.

### 상단바가 안 없어질 때 (안드로이드)

`display: fullscreen` 은 **홈 화면에 추가한 시점의 manifest 로 고정**된다.
설정을 바꾸기 전에 이미 설치해 둔 기기는 예전 `standalone` 이 그대로 남는다.

1. 먼저 화면을 한 번 탭해본다 — Fullscreen API 가 걸려 상단바가 사라진다
2. 그래도 남아 있으면 홈 화면 아이콘을 **지우고 다시 추가**한다
3. 설정 패널 > **기기 진단 정보** 를 펼쳐 `마지막 결과` 를 확인한다

진단의 `마지막 결과` 가 알려주는 것:

| 값 | 뜻 |
|---|---|
| `성공` | 전체화면 진입됨 |
| `NotAllowedError` | 사용자 조작으로 인정 못 받음 — 다른 이벤트에서 시도해야 함 |
| `TypeError: Permissions check failed` | Permissions Policy 가 막음 — 브라우저/환경 제약 |
| `시도 횟수 0` | 제스처 리스너가 아예 안 불림

### 상단바 색은 건드리지 않는다

한때 `<meta name="theme-color">` 를 호흡에 맞춰 바꿔봤으나, Chrome 이 상단바 색 전환에
자체 애니메이션을 넣어 **엇박자로 깜빡였다**(갤럭시 S24 실기기 확인). 되돌렸다.
상단바는 흰색 고정이고, 대신 전체화면으로 아예 없애는 쪽으로 간다.

### 배너 두 번 탭 = 전체화면 켜기/끄기

하단 배너를 400ms 안에 두 번 탭하면 전체화면이 켜지고, 다시 두 번 탭하면 꺼진다.
브라우저가 사용자 조작 없이는 전체화면을 허용하지 않으므로 명시적인 조작이 필요하다.

**아이폰에서는 이 기능이 동작하지 않는다. 브라우저를 바꿔도 마찬가지다.**
iPhone Safari 는 `Element.requestFullscreen` 자체를 구현하지 않았고(아이패드에는 있다),
애플 정책상 **iOS 의 모든 브라우저가 WebKit 을 쓰므로** iOS 의 Chrome · Firefox · Edge 도
똑같이 없다. 이름만 Chrome 이고 엔진은 Safari 다. 갤럭시에서 되고 아이폰에서 안 되는
이유가 이것이다.

추가로, **아이폰에서 제대로 된 standalone 앱을 만들 수 있는 것은 Safari 뿐이다.**
Chrome 등에서 홈 화면에 추가하면 주소창이 그대로 남을 수 있다.
그래서 `iosNonSafari` 를 판별해 "Safari 로 열어서 추가하라"고 따로 안내한다.

그냥 두면 두 번 탭해도 아무 반응이 없어 고장난 것처럼 보이므로,
`fsState.supported` 가 false 면 이유를 안내로 띄운다(7초 후 자동으로 사라진다).

| 상황 | 안내 문구 |
|---|---|
| iOS Safari | 공유 → “홈 화면에 추가” 하면 주소창이 사라진다 |
| iOS Chrome 등 | **Safari 로 열어서** 공유 → “홈 화면에 추가” 하라 |
| 이미 홈 화면 추가됨 | 이 기기는 상태바를 숨길 수 없다, 지금이 최대 화면이다 |
| 그 외 | 홈 화면에 추가하면 주소창이 사라진다 |

기기가 어느 쪽인지는 설정 패널 > 기기 진단 정보의 `전체화면 API` 줄로 확인한다.

관련해서 주의할 점:

- **하단 바만 `pointer-events: auto` 다.** 흰 무대는 여전히 터치 대상이 없다.
  카드가 배너에 얹혀도 '빠른 두 번 탭'이라 우연히 눌리지 않는다.
- **전체화면은 오직 배너 두 번 탭에서만 걸린다.** 예전에는 화면 아무 데나 탭해도
  자동으로 시도했으나 제거했다 — 이스터에그를 QR 찍자마자 자동 발동시키지 않기 위해서다.
- **안내 배너(`#notices`)는 하단 배너 위로 띄운다.** 겹치면 두 번 탭이 배너에 닿지 않는다.
  `app.js` 가 하단 바 높이를 실측해 `--bottombar-h` 로 넘긴다.

## 홈 화면 추가는 안내하지 않는다

예전에는 최초 방문 시 "홈 화면에 추가하라"는 배너를 띄웠으나 제거했다. 전시회에서
QR 찍고 바로 감상하는 흐름에 안 맞고, 방문객에게 설치를 권하는 것 자체가 부담이다.
지금은 주소창이 있는 상태를 기본값으로 놓고 그 안에서 카드가 들어가도록 레이아웃을
맞춘다(아래 뷰포트 절 참고). 원하는 사람은 직접 공유 버튼(아이폰) / 메뉴(안드로이드)
→ "홈 화면에 추가"로 설치할 수 있지만 화면이 그걸 유도하지 않는다.

### 뷰포트 계산 — 주소창은 항상 켜져 있다고 가정한다

이 화면은 스크롤을 완전히 막아서(`touch-action:none`) **iOS Safari 의 주소창이
접힐 방법이 없다.** 주소창은 스크롤해야 접히는데 스크롤 자체가 없기 때문이다.
그런데 CSS `vh` 단위는 iOS 에서 "주소창이 접혔다"고 가정한 큰 뷰포트를 기준으로 하므로,
`vh` 로만 계산하면 실제보다 여유 공간을 과대평가해 카드 자리가 주소창 뒤로 잘릴 수 있다.

그래서 `html`·`body`·`#app` 의 높이와 `--art-max-h` 는 전부 `vh` 를 우선 쓰고
`dvh`(현재 실제로 보이는 뷰포트)로 덮어쓴다. `dvh` 를 지원하는 브라우저(iOS 15.4+,
최신 안드로이드 대부분)에서는 항상 "주소창이 떠 있는 실제 화면" 기준으로 카드 자리를
계산하고, 지원하지 않는 구형 브라우저는 기존 `vh` 로 동작한다.

```css
height: 100vh;   /* 구형 브라우저 fallback */
height: 100dvh;  /* 실제 보이는 뷰포트 — 주소창 있는 상태 기준 */
```

아래 실측 표(다음 절)는 이 전환 전에 잰 값이라 **주소창이 없는 상태(상한)** 다.
실제로는 이보다 흰 무대가 좁다 — 실기기에서 다시 확인 필요.

## 화면 꺼짐 방지

1. `navigator.wakeLock` 을 먼저 시도한다
2. 안 되면 보이지 않는 무음 루프 영상(`assets/keepalive.mp4`)을 재생한다
3. 둘 다 실패할 때만 "자동 잠금을 끄세요" 안내를 띄운다

최초 로드 시점에는 성급하게 안내하지 않는다 — 브라우저가 사용자 제스처 전에는
거부하는 경우가 많아 대부분 오탐이 되기 때문이다.

## 카드 접촉 대응

필름 카드가 정전식 화면에 닿으면 지속 터치로 인식된다. 그래서 흰 무대에는
터치 대상이 전혀 없고, 아래 동작을 전부 차단해 두었다.

스크롤 · 핀치줌 · 더블탭줌 · 텍스트 선택 · iOS 길게누름 메뉴 ·
당겨서 새로고침 · 드래그 · 우클릭 메뉴 · `:active` 눌림 표시

## 알아둘 한계

- **웹은 실제 백라이트를 제어하지 못한다.** 어두워지는 것은 화면 위에 검은
  반투명 레이어를 덧씌우는 합성 효과이고, 체감 폭은 기기 밝기 설정에 좌우된다.
- **CSS 의 `mm` 단위는 실제 밀리미터와 다르다.** 그래서 흰 영역을 정확히
  63×88mm 로 그리지 않고, 가능한 최대로 확보하는 방식을 쓴다.
- 카드 가로 63mm 는 iPhone 15 급(화면폭 약 64.9mm)에 겨우 들어간다.
  iPhone SE 급(약 58.5mm)에서는 좌우가 물리적으로 삐져나온다.

### 흰 영역 세로 길이 — 아직 실기기 검증 전

아래는 데스크톱 브라우저에서 폰 해상도 크기의 프레임으로 잰 값이다.
**세이프에어리어(노치·홈 인디케이터)와 브라우저 주소창이 빠져 있으므로 상한이다.**
실제 폰에서는 이보다 짧고, 주소창이 있는 Safari 에서는 특히 더 짧다.

| 기기 | 프레임 측정값 (상한) | 카드 88mm |
|---|---|---|
| iPhone 15 (393×852) | 118mm | 여유 있음 |
| iPhone 15 Pro Max (430×932) | 123mm | 여유 있음 |
| iPhone SE (375×667) | 89mm | 상한에서도 아슬함 |

SE 는 상한이 89mm 라 실제로는 88mm 에 못 미칠 가능성이 높다.
게다가 SE 는 화면 가로폭이 약 58.5mm 라 63mm 카드가 좌우로 삐져나온다.

**실기기에서 확인이 필요한 항목 3가지**

1. Safari(주소창 있는 상태)에서 카드가 흰 영역 안에 세로로 다 들어가는가
2. 홈 화면에 추가한 뒤에는 들어가는가
3. 1분 이상 두었을 때 화면이 안 꺼지는가

확인 결과에 따라 상단/하단 바 높이(`styles.css` 의 `--topbar-h`, `--banner-max-h`)를
줄이면 흰 영역을 더 확보할 수 있다.

node server.js            # http://localhost:3000

## 배포 (Railway)

의존성이 하나도 없다. Node 내장 모듈만 쓰는 `server.js` 가 정적 파일을 서빙한다.

```bash
railway up
```

모든 응답은 `Cache-Control: no-cache` + ETag 재검증이다. 배너를 갈아끼우거나
코드를 고치면 바로 반영되고, 바뀐 게 없으면 304 로 끝나 트래픽 손해는 없다.

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 구조 |

| `manifest.json` | 홈 화면 추가용 |
| `assets/top-<lang>.png` · `bottom-<lang>.png` | **교체 대상** |
